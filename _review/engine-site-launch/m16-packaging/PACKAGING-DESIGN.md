# M16 packaging contract and limits

The standard local function-closure ceiling remains250000000 bytes. The fix changes no offer, price, image quality, route-attempt bound, provider budget, narration rule, identity threshold or default-off flag.

Next15's collector applies contains/dot matching after joining native paths. Windows backslashes were not normalized by that collector; the old positive test normalized both sides and hid this. New engine and personal Reader/review routes additionally lacked exclusion rules on either platform. The large baseline installer globs enumerate a dependency .env path; this is path evidence only, never a content inspection.

The build tail applies platform-neutral declared asset exclusions only to the named engine route families. Both engine and legacy traces lose credential/private-context references before file-content IO. Non-engine asset exclusions are deliberately left to Next so old media/style/bank consumers are preserved. No source file or dependency is deleted. A required-resource manifest hashes67 actual font/Style01/child-template/companion-sheet files, totaling101194402 bytes. It is packaging integrity, not a replacement for visual admission or owner acceptance.

Filtering alone still held actual Windows closures at253–267MB. Native ffmpeg/ffprobe plus required assets already nearly exhaust the limit. The build therefore losslessly gzips the exact installed platform binaries into .next/engine-native-media-v1, with closed platform/architecture/raw/compressed size and SHA bindings. Raw executable references are replaced in every trace that used them, including legacy video. Existing JS/package/license references are retained.

The lazy shared resolver validates the manifest and compressed hashes, decompresses into a fresh private0700 temporary directory, verifies raw hashes and sets executable0700 permissions. It never downloads or rewrites shared dependencies. Local unbuilt use alone falls back when no archive directory exists; a present malformed/incomplete archive refuses. Narration probe/decode arguments and legacy video settings, storage and entitlement behavior are unchanged. The build input validator refuses environment paths and executable aliases outside the dependency root before opening bytes.

Missing files, required-resource loss, escaped/sensitive aliases, unsupported trace schemas and an oversized engine closure refuse trace writes. Raw NFT backups remain under the ignored build output. Successful apply/check is idempotent; the report lists oversized legacy routes separately. LOCAL_TRACE_CONTRACT_SATISFIED is an engine-contract result, not whole-project size or deployment acceptance. allMeasuredRoutesBelowLimit is false for this project.

Linux uses an isolated Node22.19 Alpine3.22/musl userspace in the already installed WSL environment, its own npm-ci dependencies and explicit Prisma generation. Docker daemon was unavailable; no account/license acceptance, OS install or remote builder was used. The Docker Desktop distro identity causes Prisma's automatic target detection to choose Debian; only the copied local Linux recipe overrides the query-engine library to the downloaded matching musl version. No production Prisma setting or schema changes. This is not Vercel's glibc/adapter/private-target qualification.

Windows uses shared node_modules read-only, denied env reads, fake literal build values, public Google Font GET only, and an ignored generated-metadata overlay for tsconfig/next-env. Source compiler settings/aliases and lint were not relaxed; the pre-existing Next ignoreBuildErrors flag remains unchanged and both separate TypeScript gates pass.

Remaining deployment blocker: Linux has16 oversized legacy routes, maximum334920241 bytes. Keep their full list in the measured report. Before deploy, review their actual consumers and split metadata imports from rendering dependencies or define justified per-route assets. Do not disable routes, drop legacy assets blindly, raise the ceiling or treat a new-engine result as a project-wide PASS.
