# R1D Chameleon Action Representability Calibration — Decision Gate

Status: approved for `$0` investigation by Guy's instruction to continue after
the pushed mixed Source-Evidence scheduler PASS, prove the new-story path
offline before spending, and return every implementation milestone to Claude
Code for independent QA.

## 1. Proposed change

Add a generic review-evidence-only Action Semantic representability audit and
exercise it against the canonical eight-page `chameleon_koko_bedtime` Story
Source plus its canonical visual directions. The audit receives explicit
reviewed intents; it never infers a predicate from prose and never grants
Candidate, reconciliation, Wizard, render, or production authority.

## 2. Why now?

Historical failed drafts were intentionally not persisted. Receipts prove the
number and location of capability gaps but not which predicate or semantic
shape the provider attempted. Guessing from the story would repeat the evidence
grain error already corrected by Codex and Claude.

The current catalog comparison also conflates three different cases:

1. a predicate is absent (`runs`);
2. a predicate exists but rejects the required subject/object domain
   (`walks`/`waves`/`opens` with an anthropomorphized prop subject, `turns`
   with an object);
3. a beat belongs to static/ambient presentation or still requires product
   review rather than an Action Catalog entry.

## 3. Scope

General offline audit function, one exact canonical-story regression, and
durable evidence. No Action Catalog, prompt, schema, policy, request, receipt,
Wizard, render, or Story Source change.

## 4. Risk of hardcoding

The audit function contains no story key, page, companion, phrase, predicate
recommendation, or Source Evidence ID. Chameleon-specific reviewed intents live
only in the test/evidence layer and are explicitly non-authorizing.

## 5. Files likely affected

- `lib/visual-contract-compiler/actionSemanticRepresentabilityAudit.ts`
- `lib/__tests__/chameleon-action-representability.spec.ts`

## 6. Expected behavior after change

For each explicitly reviewed beat, the audit reports exactly one of:

- representable Action Catalog authority;
- representable presentation/non-visual authority;
- a closed catalog/rule mismatch list;
- product/semantic review still required.

It validates safe page/beat/Source Evidence identity, returns no source phrase,
contract value, prompt, response, or raw draft, and carries `authorizes: []`.

The exact Story Source + visual direction experiment must also expose any
non-action blocker rather than silently rewriting the source or visual plan.

## 7. Validation plan

1. exact reviewed Chameleon map backed by current Source Evidence IDs;
2. assertions that existing valid actions, missing predicates, subject-domain
   gaps, object-rule gaps, presentation states, and review-required beats remain
   distinct;
3. duplicate/malformed identity rejection and privacy assertions;
4. production compiler/harness execution at `$0` against an eight-page
   visual-direction-shaped draft;
5. focused compiler/catalog/presence tests, TypeScript, literal repository
   check, and diff-check;
6. focused local commit and independent read-only Claude Code review.
